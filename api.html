Quick Start
Up and running in seconds
Live AQI by city GET

Fetch current air quality for a city. No key is needed right now.

# Request curl "https://api.aqi.jeff-o-blogs.com/api/aqi/city?city=Bangkok&country=Thailand"
// Response (abridged) { "success": true, "data": { "name": "Bangkok", "aqi": { "us": 87, "cn": 74 }, "mainPollutant": "p2", "weather": { "temperature": 34, "humidity": 62 } } }
Nearby stations by GPS GET

Find monitoring stations around any coordinate. Combines IQAir, PurpleAir community sensors and OpenAQ where available.

# Request curl "https://api.aqi.jeff-o-blogs.com/api/aqi/nearby?lat=13.756&lon=100.501&radius=50"
// Response (abridged) { "success": true, "data": { "stations": [ { "name": "Bangkok", "source": "IQAir", "distance": 2.4, "aqi": { "us": 87 } } ] } }
Recorded history GET

Readings we have recorded within about 15 km of a point, with min / max / average. hours defaults to 24. Readings are kept for 90 days.

# Request: last 7 days (168 hours) curl "https://api.aqi.jeff-o-blogs.com/api/history?lat=18.788&lon=98.985&hours=168"
// Response (abridged) { "success": true, "data": { "count": 84, "stats": { "min": 88, "max": 145, "avg": 112 }, "readings": [ { "timestamp": "2026-11-21T06:00:00.000Z", "aqi": 112, "source": "IQAir" } ] } }
JavaScript fetch example JS

Drop this into any frontend project. No SDK required: it's a plain REST API.

// Fetch Bangkok AQI const url = 'https://api.aqi.jeff-o-blogs.com/api/aqi/city' + '?city=Bangkok&country=Thailand'; const res = await fetch(url); const { data } = await res.json(); console.log(`AQI: ${data.aqi.us}`);
Reference
Available endpoints

Base URL: https://api.aqi.jeff-o-blogs.com · All endpoints use GET and return JSON.

Endpoint Description
GET /health Service health check.
GET /api/aqi/city Live AQI for a named city. Params: city, country, state (optional).
GET /api/aqi/nearby Stations near GPS coordinates. Params: lat, lon, radius (km, default 50).
GET /api/aqi/countries List of supported countries.
GET /api/aqi/states List of states / provinces. Param: country.
GET /api/aqi/cities Cities within a state. Params: state, country.
GET /api/history Recorded readings within ~15 km of a point, plus min / max / average. Params: lat, lon, hours (default 24). Data is kept for 90 days.

FAQ
Common questions
Where does the data come from?
Live readings come from IQAir's network of monitoring stations, supplemented by PurpleAir community sensors and OpenAQ stations where they are available nearby.
How is history recorded?
A background job records readings for a watch list of more than 200 places: key local spots every 2 hours, Thai provinces daily, and European and world cities every 6 hours. History is only available near those places and is kept for 90 days.
Is Thailand coverage better than other regions?
Yes. All 75 Thai provinces with a recorded reading are on the watch list, and we fall back to the nearest station when a named station is not available.
Do I need an API key?
Not at the moment. The API is in early access and open to use. Please be reasonable with request volume: upstream data providers limit how often we can refresh.
What happens if I send too many requests?
Upstream providers may rate-limit us, in which case you may see a 429 or an error response. Cached results are reused for a few minutes, so repeated identical requests are cheap.
Will there be paid plans or higher limits?
Possibly in future. If you need higher volume, custom places or research access, describe it in the form above.
